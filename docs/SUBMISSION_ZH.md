# Afterbell 六部分项目说明

赛道：AI Trading Desk · 信息提炼与信号生成

1. 思路与核心逻辑
美股休市后，公告仍在发布，但原生股的最后报价可能已经过期，股票永续又是不同的交易工具。我们的核心假设是：先核验事实与时间，再判断业务和资产影响，最后检查是否具备作判断的数据条件，比直接输出新闻摘要更有助于减少无依据的交易判断。此假设尚待真实用户验证。Afterbell 把“事件→业务影响→资产影响”拆成可检查的链条；事实必须关联已获取证据与原文片段，推断另列不确定性、反证和下一步验证。证据不足时允许返回“暂无法判断”。产品不以预测收益或跨市场套利为承诺。

2. 目标用户与产品价值
面向持有或研究 AAPL、MSFT、NVDA 的个人交易者，尤其是亚洲时区、在美国休市期间接触事件消息、采用人工决策且关注事件风险的人。当前默认平衡风险偏好，支持保守/积极和下一交易时段/一周/一月窗口。资金规模与交易频率尚未通过用户访谈验证，不虚构画像数据。用户输入问题，可指定官方公告，得到证据、事件时间线、影响链、市场检查、反证、失效及等待条件，并保存、回看和导出研究。价值在于判断依据可检查，不代替最终投资决定。

3. 验证数据与关键指标
实测：29项软件测试通过，生产构建成功；真实公网任务于2026-10-03完成，DeepSeek调用、保存和Markdown/JSON导出均已验证，耗时33.0秒，获得13份真实资料，16项工具尝试中9项成功，整体partial，失败项保留可见。十个真实历史事件完成普通模型摘要与Afterbell同模型对比，记录结构、原文引用、Token和耗时；另十个人工压力场景仅作测试，公开研究接口拒绝case模式。以上不是准确率、用户完成率或收益证明。历史正文事后抓取，模型可能知道后续事件。同模型语义复核不是独立审计。真实测试用户0名；已准备三人交叉任务协议，目标是验证找原文、识别行情缺口及理解等待结论的完成率、耗时和误解。账单金额与长期留存未核验，不声称成本优势或已有分发规模。

4. 完成度与技术
Next.js/TypeScript/SQLite实现真实研究、进度、访客隔离、历史和导出，服务端使用OpenAI兼容接口接入DeepSeek，当前配置deepseek-flash。公司公告、SEC、公司博客、美联储等资料优先；使用官方Bitget只读SDK实际取得股票永续身份、报价、盘口和历史。原生股备用接口核验Nasdaq/EQUITY/USD身份；SEC提供已披露GAAP财务，Nasdaq提供EPS预期，财政部提供日收益率。原生股、永续与代币化资产不会混淆，未取得的rToken信息不伪造。模型输出先结构与引用校验，再由同一模型做语义复核；资料内容按不可信输入处理。官方原始美股MCP部分服务仍不可用，实际失败轨迹保留；备用接口的许可、延迟和SLA未完全确认。周末报价仅作历史观测，不据此计算可成交套利。公共Demo不配置账户交易权限，仅接受实时取数任务。已部署至腾讯云东京服务器，HTTPS及实际模型研究、保存导出通过验收。原生股Yahoo限流时改用实际Nasdaq日期级报价，保留延迟和字段缺口。下一步是真实用户验证及独立语义评估。

6. 对AI Trading的理解
我们认为研究系统应明确“何时不该形成交易判断”：资料成功获取不代表事件相关，产品进展不代表财务贡献，已披露利润不代表超预期，行情快照不代表可成交价格。模型适合提取与组织证据、提出条件化解释；人的最终决策和对数据缺口的理解不可省略。希望官方只读接口提供稳定错误状态、报价时段与时间字段，减少跨资产误比较。

## 大模型作用

使用DeepSeek，当前服务端配置deepseek-flash，通过OpenAI兼容API调用。模型从实际取得的证据生成事实、推断、事件→业务→资产影响链、反证、失效及等待条件；每项关键事实要求证据ID和原文片段。应用做结构、引用关联与原文匹配校验，再由同一模型复核事实是否被引文支持，移除不支持内容并抑制依赖它的结论。这仍可能有语义错误，并不是独立事实审计。模型不生成行情、不编造来源、不控制交易账户。代码开发由Codex辅助；运行时研究使用DeepSeek。Qwen额度使用情况未确认，不申报已使用。
